Data flow

The path a filter change takes from the UI to a rendered chart. The same pattern applies to every filtered view.

1
User sets filter
FilterBar writes to shared refs in useFilters: period, location, category, status
2
View reacts
A watcher calls getCurrentFilters(), which maps period to month and location to warehouse
3
api.js request
Builds query params, omits any "all" values, then issues an axios GET to :8001/api/...
4
FastAPI filters
apply_filters and filter_by_month run list comprehensions over in-memory data
5
Validate and return
Pydantic response_model shapes the JSON. Summary and report routes return untyped dicts
6
Render
Raw results go into refs; KPIs, tables and SVG charts derive from computed properties

Where filtering happens

Filtering is split between server and client. Orders and inventory are filtered on the server. Backlog and Demand are unfiltered on the server, so their views cross-reference the filtered inventory SKUs on the client. Inventory has no time dimension, so the period filter has no effect on it.

State model

There is no Pinia or Vuex. Cross-view state lives in module-level refs inside composables (a singleton pattern), so filter selections persist as you navigate between views. Locale and the mock user follow the same pattern.

Gaps and risks

Issues I found while mapping the system. They are acceptable for a demo, but they matter if this becomes a reference implementation or goes in front of a client.

High

Client calls endpoints the server does not have

The tasks modal in App.vue calls /api/tasks for get, create, toggle and delete. The server returns 404 for all of these, so task features fail at runtime. The purchase-order functions in api.js point at routes that don't exist either, although nothing calls them yet.

Medium

Hard-coded API base URL in two places

api.js and Reports.vue both hard-code http://localhost:8001. Nothing reads it from the environment or a Vite proxy, so any deployment other than localhost needs code changes.

Medium

Time logic is pinned to 2025

QUARTER_MAP and the quarterly report only recognise 2025 dates. Orders from any other year are silently dropped from quarter filters and quarterly reports.

Medium

Month filter uses substring matching

filter_by_month checks month in order_date rather than parsing the date, so it relies on the format staying exactly YYYY-MM-DD.

Low

Unrouted view and inconsistent typing

Backlog.vue exists but has no route. Summary, spending and report endpoints return untyped dicts, while the other endpoints use Pydantic response_model.

Low

Demo-only security posture

There is no authentication (the user is a hard-coded mock), CORS is open to every origin, and there is no rate limiting. This is fine on localhost. It must change before any shared or hosted use.

Low

No frontend test coverage

Backend endpoints have pytest coverage. The roughly 6,900 lines of Vue have none, and the missing /tasks routes went unnoticed as a result.
